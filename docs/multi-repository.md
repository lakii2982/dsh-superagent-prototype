# 多仓库管理与飞书群绑定

本版本提供统一管理入口、单一飞书接入、每仓库独立 DSH 运行实例，以及当前仓库串行执行。默认单仓库模式保持兼容。

## 启动管理入口

在新建的 DSH Web profile 安装此 bundle 后，将该 profile 的 `cordis.patch.yml` 设置为以下内容。不要覆盖个人已有 profile：

```yaml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082
- id: dsh-superagent
  config:
    mode: manager
    stateDir: /absolute/path/to/manager-state
- id: dsh-superagent-github
  disabled: true
- id: dsh-superagent-feishu
  disabled: true
```

运行 `dsh --profile <manager-profile> --no-open`，用启动输出中的浏览器链接访问，在侧栏打开 Superagent。管理入口不直接加载单仓库 GitHub / 飞书来源。

首次安装仍要求 DSH、Node、Git 和已认证的 CLI。本版向导覆盖插件安装后的配置，不替代外部应用创建、授权或模型账号登录。

## 配置流程

1. 连接只允许机器人身份的飞书 CLI。仓库也可以在连接机器人前先登记。
2. 添加已有本地仓库：名称、Git 根目录、GitHub 远端和执行账号 CLI。保存时检查目录与远端，以及账号的推送权限。
3. 从机器人已加入的群读取成员，选择允许发起任务的人。GitHub 与飞书的允许列表独立。
4. 刷新群列表，将群绑定到仓库。一个群只能有一个绑定，一个仓库可以绑定多个群。
5. 启动仓库实例。默认同目录串行，至多同时运行三个仓库。
6. 通过“打开仓库工作空间”进入该实例，确认模型可用。随后由允许的用户在绑定群 @机器人发起试单。

本机已有 CLI 同时支持个人身份时，可使用 `scripts/lark-bot` 作为仅机器人入口，设置 `DSH_SUPERAGENT_LARK_CLI` 为实际 CLI 或已有机器人 wrapper 的绝对路径。该入口固定 `--as bot`，拒绝个人身份和配置变更，不修改原 CLI 的全局策略或登录。

安装绑定和本地自检本身不发送群消息。若用户已明确提供群 ID，但机器人暂不可访问，可通过管理 API 保存 `enabled: false` 的待启用绑定；启用时仍必须通过群列表检查。

## 执行与会话

- 每个仓库独立 DSH_HOME、profile、进程、状态目录和本地连接凭据；会话与工作空间不与管理入口共用存储。
- 每个工单保留自己的持久会话，在真实仓库根目录执行，共用对应 DSH 工作空间。
- 同目录工单串行，人工追问不会获得额外修改名额。后台命令仍运行时继续占用目录。
- 已有用户修改会阻止新工单开始，不自动 stash、reset 或清理。
- 当前目录采用协作锁，避免另一个同模式实例同时接管；锁不是文件权限隔离。
- 已有工单固定原目录。存在开放的当前仓库工单时，不允许切换工作方式或路径。
- 同一目录准备失败会留下持久状态，重试不会仅凭目录存在就认定准备成功。

独立 profile 的会话不保证自动出现在个人 profile 的侧栏。使用管理入口提供的实例入口访问；实际工作空间与会话仍由 DSH 持久化管理。

## 消息可靠性与绑定变更

消息先写入管理 SQLite 队列，再投递给目标实例。跨进程采用至少一次投递，由稳定 Trigger ID 消重。失败按退避重试，不更换目标仓库；各仓库独立排队。

话题首次归属固定后，群换绑只影响新话题。旧话题的追问继续交给原仓库，包含结束后恢复的工单。开放工单或未送达消息会阻止换绑。首次接入不执行绑定生效前的历史新需求。

停用群会暂停自动接单和自动回复，队列保留。暂停调度不等同于停止正在运行的任务；停止实例才会终止其进程。

机器人身份一旦已有话题路由便不能直接替换，以免复用另一应用的标识。尚无路由和工单时可修正误选的机器人。

## 运行与故障处理

管理数据库：`<stateDir>/manager.sqlite`。
仓库数据库：`<stateDir>/repositories/<repositoryId>/orchestrator.sqlite`。
实例启动日志：`<stateDir>/logs/<repositoryId>.log`。
生成的 DSH profile：`<stateDir>/repositories/<repositoryId>/dsh-home/profiles/superagent-<id前八位>`。
模型凭据文件可复用操作者现有配置；会话及工作空间存储严格分开。

管理入口重启不会主动停止仓库实例，会通过独立凭据重新发现它们。仓库实例只在用户点击启动时启动；不提供自动开机启动。

群无法读取时，先检查机器人是否属于群所在租户、是否已加入群、是否拥有所需应用权限。个人用户身份能读到群，并不说明机器人也能读到。

所有管理接口仅监听回环地址；实例间使用各自的凭据，浏览器页面不获取实例凭据。执行器仍以当前系统用户运行，目录与命令 wrapper 不是安全沙箱，当前版本面向同一操作者信任的本地仓库。

## 已有部署与回退

本版本不自动迁移运行中的旧部署或会话历史。先使用独立的管理 profile 接入新仓库，旧 profile 与数据库保持原状，避免双重消费同一机器人事件流。

迁移已有仓库前，先停止旧消费者与执行实例，备份数据库和 DSH 会话数据，并明确如何承接开放工单及切换期间的消息。仅复制配置不等于迁移工单；不得在旧消费者仍工作时启用新入口。

回退到旧版本时，先停用新入口的群绑定并停止对应实例，保留管理数据库及未送达记录。不能只还原旧数据库后丢弃新入口已经确认接收的消息。

## 验证范围

自动化测试覆盖仓库根目录 / 远端检查、串行名额、跨仓库路由、重复事件、重启恢复、失败重试、群换绑、实例鉴权、共享机器人命令范围和回复幂等。另以临时 DSH profile 检查真实页面加载。

真实飞书群的接入、模型执行和外部回复必须分别确认。没有实际发起试单时，不把本地测试通过描述成端到端交付已验证。
