# 多仓库管理与飞书群绑定

桌面版进入侧边栏的 **Superagent**，点击 **启用多仓管理**。切换后进入统一的接入配置页。原单仓数据保留在原状态目录，企业管理器使用独立目录。仓库全部停止后，可以从管理页面返回单仓模式。

在 **仓库管理** 为每个仓库填写所属团队和产品线，再登记本地 checkout、GitHub 仓库和执行账号。全公司只使用一个管理页面。使用飞书时，从 **飞书机器人** 添加一个或多个机器人，再到 **群聊绑定** 依次选择机器人、该机器人已加入的群、目标仓库和允许接单的群成员。一个机器人可连接多个群，每个“机器人＋群”只能对应一个仓库；一个仓库可接收多个群或多个机器人的任务。完成接入后启动仓库，再用获授权账号发一张小工单验证。

本版本提供统一管理入口、多机器人飞书接入、每仓库独立 DSH 运行实例，以及当前仓库串行执行。默认单仓库模式保持兼容。

## 启动管理入口

在新建的 DSH Web profile 安装此 bundle 后，将该 profile 的 `cordis.patch.yml` 设置为以下内容。不要覆盖个人已有 profile：

```yaml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082
- id: dsh-superagent
  config:
    mode: manager
    stateDir: /absolute/path/to/manager-state
- id: dsh-superagent-github
  disabled: true
- id: dsh-superagent-feishu
  disabled: true
```

运行 `dsh --profile <manager-profile> --no-open`，用启动输出中的浏览器链接访问，在侧栏打开 Superagent。管理入口不直接加载单仓库 GitHub / 飞书来源。

管理入口和其他部署使用同一个面板：左侧栏上方是管理页（仓库、投递与状态、群聊绑定、飞书机器人），下方列出已登记仓库；选中仓库后，同一左栏继续给出该仓库的收件箱、任务、仓库、来源、触发、评估、提示词和设置。这些页面由管理入口代理到该仓库独立的 DSH 实例，浏览器不会拿到实例凭据。会话仍属于各仓库自己的实例，面板里的 Session 按钮会改为打开该仓库的工作空间。

主机需已安装 DSH、Node、Git、Python 3 和支持命名档案的飞书 CLI。管理员可从工作台发起飞书扫码创建机器人，已有机器人通过本机账号档案发现。

## 飞书授权与业务恢复

仓库设置和群绑定读取群成员时，权限不足会显示当前应用的权限申请页和二维码。链接和二维码均指定应用身份（tenant_access_token）。在「应用身份权限」中确认开通，免审标记表示该权限的审核要求。桌面窗口保持原仓库、机器人、群和未保存的选择。页面在返回窗口时及每隔 15 秒读取一次原资源，10 分钟后暂停自动检测，可手动继续。能成功列出成员时，页面恢复名单，用户继续选择并保存。二维码生成失败时仍可打开同一申请链接。

下表是各场景的产品验收口径。应用创建由目标飞书账号确认，真实事件交付需要在目标租户验收。

| 场景 | 人工动作 | 验收与恢复条件 |
| --- | --- | --- |
| 首次连接、密钥轮换 | 选择本机已配置的机器人，或在工作台发起扫码创建 | 服务端以机器人身份验证租户、应用和机器人。重连必须匹配已登记身份 |
| 读取群列表 | 应用管理员确认查看群信息的权限，按飞书要求发布或提交审批 | 原机器人重新列群成功，群选择器更新。空名单还要检查机器人是否已入群 |
| 机器人被移出群、外部群限制 | 群管理员打开目标群，确认群规则并添加机器人。外部群还涉及应用对外共享范围 | 原机器人可见目标群，重新读取该群成员成功 |
| 读取成员、保存接单人 | 应用管理员从专属链接或二维码开通查看成员权限 | 读取同一群的完整名单后恢复草稿。飞书应用权限和仓库接单名单分别生效 |
| 实时接单 | 应用管理员配置接收消息的事件和长连接，获授权成员在绑定群发起一次试单 | 同一条事件到达对应仓库。长连接建立和真实事件到达分开检查 |
| 历史消息、话题和图片 | 按失败操作检查消息读取权限、资源权限、资源可见性 | 使用同一话题或图片复核。历史读取失败时独立显示，保留成功的实时接入状态 |
| 回复消息 | 应用管理员开通发消息权限，群管理员处理禁言或成员资格 | 原投递按既有幂等键恢复，检查原话题的发送回执 |
| 网络异常、限流、资源被删除 | 网络恢复或按限流窗口重试，失效资源单独处理 | 根据实际错误分类。申请应用权限无法恢复已删除资源 |
| 将来需要以个人身份访问资源 | 为明确的用户操作单独发起设备授权，展示飞书签发的验证链接 | 仅在用户确认后恢复该用户的原操作。拒绝、取消、过期都保留原草稿并允许重新发起 |

应用审批和版本发布进度以飞书官方页面为准。本端通过原业务请求确认生效。管理员转发申请链接时，链接只携带应用标识与权限名称。扫码后仍要由具备权限的账号在飞书确认。

## 配置流程

1. 在“飞书机器人”选择账号下的机器人并验证连接；本机未配置时可扫码创建新机器人。每个连接显示独立身份、加入的群、绑定数量和运行状态。仓库也可以在连接机器人前先登记。
2. 在“仓库”添加已有本地仓库：名称、Git 根目录、GitHub 远端和执行账号 CLI。保存时检查目录与远端，以及账号的推送权限。
3. 选择机器人，从它已加入的群读取成员，选择允许发起任务的人。GitHub 与飞书的允许列表独立，各机器人的飞书身份也分别授权。
4. 在“群聊绑定”刷新所选机器人的群列表，将群绑定到仓库。同一“机器人＋群”只能有一个绑定；同群的不同机器人可以分别指向不同仓库。多个群、多个机器人也可以指向同一仓库。
5. 在“仓库”启动仓库实例。默认同目录串行，同时运行三个仓库。运维可在管理 profile 的 `dsh-superagent` 配置中设置 `maxRunningRepositories`，允许值为 1～12，启动中的仓库也占用名额。
6. 通过“打开仓库工作空间”进入该实例，确认模型可用。随后由允许的用户在绑定群 @机器人发起试单；投递积压和暂停调度在“投递与状态”。

工作台从本机飞书 CLI 读取账号档案，按可用账号名展示机器人。飞书未提供账号名时，显示机器人名称和应用标识供核对。扫码创建会生成独立命名档案，确认后自动刷新候选列表。连接时服务端重新核对应用和机器人身份，运行时使用随插件提供的机器人专用入口和选定档案。原有独立 CLI 连接可直接重新验证。

安装绑定和本地自检本身不发送群消息。若用户已明确提供群 ID，但机器人暂不可访问，可通过管理 API 保存 `enabled: false` 的待启用绑定；启用时仍必须通过群列表检查。

## 执行与会话

- 每个仓库独立 DSH_HOME、profile、进程、状态目录和本地连接凭据；会话与工作空间不与管理入口共用存储。
- 每个工单保留自己的持久会话，在真实仓库根目录执行，共用对应 DSH 工作空间。
- 同目录工单串行，人工追问不会获得额外修改名额。后台命令仍运行时继续占用目录。
- 已有用户修改会阻止新工单开始，不自动 stash、reset 或清理。
- 当前目录采用协作锁，避免另一个同模式实例同时接管；锁不是文件权限隔离。
- 已有工单固定原目录。存在开放的当前仓库工单时，不允许切换工作方式或路径。
- 同一目录准备失败会留下持久状态，重试不会仅凭目录存在就认定准备成功。

独立 profile 的会话不保证自动出现在个人 profile 的侧栏。使用管理入口提供的实例入口访问；实际工作空间与会话仍由 DSH 持久化管理。

## 消息可靠性与绑定变更

消息先写入管理 SQLite 队列，再投递给目标实例。跨进程采用至少一次投递，由稳定 Trigger ID 消重；新机器人的消息、话题和回执具有各自的命名空间，同群中的同一消息不会在不同机器人之间误去重。失败按退避重试，不更换目标仓库或发送机器人。每个机器人独立维护事件连接、补收游标与错误状态。

话题首次归属固定后，群换绑只影响新话题。旧话题的追问继续交给原仓库，包含结束后恢复的工单。开放工单或未送达消息会阻止换绑。首次接入不执行绑定生效前的历史新需求。

停用一个机器人的连接会暂停它负责的群及队列，不停止其他机器人的连接。停用某个群绑定只暂停该“机器人＋群”的自动接单和自动回复，队列保留。暂停调度不等同于停止正在运行的任务；停止实例才会终止其进程。

修改连接的 CLI 时必须仍对应原来的应用及机器人身份。使用另一个机器人时新增连接，再配置群绑定；有绑定或历史记录的机器人不能直接删除。每条回执沿原请求的机器人身份发送，读取消息与成员也按该身份核验。

## 运行与故障处理

管理数据库：`<stateDir>/manager.sqlite`。
仓库数据库：`<stateDir>/repositories/<repositoryId>/orchestrator.sqlite`。
实例启动日志：`<stateDir>/logs/<repositoryId>.log`。
生成的 DSH profile：`<stateDir>/repositories/<repositoryId>/dsh-home/profiles/superagent-<id前八位>`。
模型凭据文件可复用操作者现有配置；会话及工作空间存储严格分开。

管理入口重启不会主动停止仓库实例，会通过独立凭据重新发现它们。仓库实例只在用户点击启动时启动；不提供自动开机启动。

群无法读取时，先检查机器人是否属于群所在租户、是否已加入群、是否拥有所需应用权限。个人用户身份能读到群，并不说明机器人也能读到。

一个机器人服务多个群时，这些群共享该机器人的连接与应用权限；停用或连接故障会同时影响这些群。需要独立运维的团队可分别登记机器人，继续共用同一套 DSH。授权按机器人和仓库保存，并不因机器人加入某个群就自动放开仓库访问。

“身份已连接”表示 CLI 身份验证成功，实时收消息需再看实时事件状态。历史读取失败独立显示：例如 `230027` 表示操作权限不足，会影响历史补收和上下文读取，但不会因此关闭实时监听。按[飞书群历史 API 文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)核对应用权限；仅收到 @ 消息不代表拥有群历史读取权限。调整应用权限后，仍需分别验证实时消息、历史上下文和回复。

所有管理接口仅监听回环地址；实例间使用各自的凭据，浏览器页面不获取实例凭据。执行器仍以当前系统用户运行，目录与命令 wrapper 不是安全沙箱，当前版本面向同一操作者信任的本地仓库。

## 已有部署与回退

团队试点使用新 profile，并参考[企业研发试点部署与验收](014-enterprise-development-pilot.zh-CN.md)。

管理器升级会把原单机器人连接迁入机器人列表，保留原群绑定、消息队列和历史工单的标识；新增机器人使用独立命名空间。升级前仍需备份完整部署。

本版本不自动迁移其他运行中的独立部署或会话历史。先使用独立的管理 profile 接入新仓库，旧 profile 与数据库保持原状，避免双重消费同一机器人事件流。

迁移已有仓库前，先停止旧消费者与执行实例，备份数据库和 DSH 会话数据，并明确如何承接开放工单及切换期间的消息。仅复制配置不等于迁移工单；不得在旧消费者仍工作时启用新入口。

回退到旧版本时，先停用新入口的群绑定并停止对应实例，保留管理数据库及未送达记录。不能只还原旧数据库后丢弃新入口已经确认接收的消息。

## 验证范围

自动化测试覆盖仓库根目录 / 远端检查、串行名额、跨仓库路由、重复事件、重启恢复、失败重试、群换绑、实例鉴权、多机器人命令范围、同群跨机器人隔离和回复幂等。另以临时 DSH profile 检查真实页面加载。

真实飞书群的接入、模型执行和外部回复必须分别确认。没有实际发起试单时，不把本地测试通过描述成端到端交付已验证。
